# 03 · 先质疑问题定义

> 原始指令：不要默认我提出的问题定义就是正确的。你先分析我真正想解决的底层需求，判断我有没有把症状误认为原因、把手段误认为目标。如果存在更值得解决的问题，直接指出来。

**用户原始问题：** $ARGUMENTS
（如果这里为空或显示为字面量 `$ARGUMENTS`，就分析用户在当前对话中最近提出的问题或需求。）

## 执行步骤

1. **复述字面问题**，一句话。
2. **往上追目的**：问"做这件事是为了什么"，连续追 3 到 5 层，直到碰到真正的目标（用户价值、业务结果、个人目标）。
3. **逐项诊断：**
   - 症状 vs 原因：说的是表面现象，还是产生它的机制？
   - 手段 vs 目标：要的这个东西，是不是只是达成目标的一种手段？还有更便宜的手段吗？
   - XY 问题：是不是卡在自己想出来的解法 Y 上，而真正的问题是 X？
   - 局部 vs 全局：在局部做到最好，会不会让整体变差？
   - 这个问题是否本来就不该存在：能不能把产生它的条件消掉？
4. **下判断**：原问题定义「成立 / 部分成立 / 不成立」，给出理由。
5. **如果有更值得解决的问题，直接指出来**：写出重新定义后的问题陈述，比较原问题和新问题的收益与成本。
6. **给建议**：解决原问题、解决新问题，还是两者都做，以及下一步具体做什么。

## 原则

- 直接说，不绕弯子，不铺垫。
- 如果原问题定义本来就是对的，明确说"你的定义没问题"，然后继续干活。不要为了显得有洞见而硬反驳。
