# 02 · 先对齐，再出 3 版方案

> 原始指令：先问一些不清晰的问题，对齐我的喜好，然后再出 3 版方案。

**任务：** $ARGUMENTS
（如果这里为空或显示为字面量 `$ARGUMENTS`，就以当前对话中正在讨论的任务为准。）

## 第一阶段：提问（问完必须停下）

1. 先自己读上下文：代码、文档、对话历史。**能自己查到的不要问。**
2. 提 3 到 7 个问题，只问**答案不同会让方案明显不同**的问题。按影响从大到小排序。
3. 每个问题都给出选项和你的默认推荐，方便用户一个字回答，例如：
   `Q1 目标用户是谁？ A. 新手 B. 专业用户 C. 都要（默认 A，理由：……）`
4. **问完就停，等用户回答。** 不要在同一条回复里接着出方案。
5. 如果用户回答"你定 / 随便"，就按默认推荐走，并在方案开头写明你做的假设。

## 第二阶段：出 3 版方案

- 3 版之间必须在**取舍维度上真正不同**（不同架构路线、不同优先级，或保守 / 平衡 / 激进），不能是同一方案的小号、中号、大号。
- 每版包括：
  - **一句话核心思路**
  - **具体做法**（关键步骤或结构）
  - **优点**
  - **代价与风险**
  - **工作量估计**
  - **最适合什么情况**
- 最后给一张对比表，并明确说出**你推荐哪一版、为什么**。哪一版最贴合第一阶段的回答，就要说清楚是哪几条回答决定的。
