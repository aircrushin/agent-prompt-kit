# 01 · 第一性原理修复

> 原始指令：从第一性原理出发，找到最本质原因，修复一下。

**目标问题：** $ARGUMENTS
（如果这里为空或显示为字面量 `$ARGUMENTS`，就以当前对话中正在讨论的问题为目标。）

## 执行步骤

1. **只写事实。** 列出可观察的现象、触发条件、环境、复现步骤。把"事实"和"猜测"分成两栏，不要混在一起。
2. **一层层往下拆。** 连续追问"为什么会这样"，直到触到不能再拆的底层事实：数据流、状态、契约（接口/类型/约定）、时序、资源。每一层都要有证据：代码行、日志、复现结果。
3. **列至少 2 个互相竞争的假设，并逐个证伪。** 用最小实验（加日志、写最小复现、二分 git bisect）排除，不靠直觉选一个。
4. **确认根因的三条标准**，缺一不可：
   - 能解释**所有**观察到的现象；
   - 去掉它，问题消失；
   - 能据此预测一个还没观察到的现象，并验证成立。
5. **在根因层修复。** 做最小、正确的改动。禁止用这些手段冒充修复：吞掉异常的 try/catch、针对某个值的特判、sleep/重试掩盖时序问题、改测试迁就错误行为。如果必须先止血，明确标注"临时止血"，并单独列出根治项。
6. **验证并扩散检查。** 把复现用例变成回归测试；用 grep 搜索代码库里同一根因的其他出现点，一并列出。

## 输出格式

- **现象**：一句话
- **因果链**：现象 ← 直接原因 ← … ← 根因（每一环附证据）
- **根因**：一句话 + 证据
- **修复**：改了什么、为什么在这一层改
- **验证**：测试 / 复现结果
- **同类风险**：其他可能踩到同一根因的位置
